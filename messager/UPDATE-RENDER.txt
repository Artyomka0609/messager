Обновление мессенджера — 10 октября 2026

Подключать GitHub к Codex или устанавливать Git не нужно.
Исправление состоит из двух файлов: server.py и public/app.js.

1. Откройте https://github.com/Artyomka0609/messager в браузере под своим аккаунтом.
   В корне репозитория выберите Add file -> Upload files.
   Загрузите исправленный server.py вместо старого и нажмите Commit changes.

2. Откройте папку public в репозитории.
   Через Add file -> Upload files загрузите исправленный app.js вместо старого
   и нажмите Commit changes. Важно: app.js должен находиться в public.

3. Откройте сервис messager в Render и дождитесь успешного развёртывания
   последнего изменения. Если автоматическое обновление выключено,
   выберите Manual Deploy -> Deploy latest commit.

4. В настройках Render должна быть переменная DATABASE_URL с адресом вашей
   базы Neon. Не публикуйте её в репозитории и не присылайте пароль в чат.
   Команда сборки: pip install -r requirements.txt
   Команда запуска: python server.py
   При первом запуске исправленный сервер сам добавит недостающие колонки
   в базу. Переписка и существующие вложения не удаляются.

5. Откройте https://messager-o0ox.onrender.com и обновите страницу Ctrl+F5.
   Отправьте небольшое фото и обычный файл, перезагрузите страницу, откройте
   чат заново и проверьте скачивание с обоих аккаунтов.

Что исправлено:
- Повторное добавление avatar больше не срывает миграцию колонки image в PostgreSQL.
- Сервер больше не отбрасывает вложение при неполной схеме базы.
- Большие сообщения WebSocket собираются из всех частей до обработки JSON.
- Успешная отправка подтверждается только после записи сообщения и файла в базу.
- При ошибке записи отображается «Не отправлено».
- Без соединения выбранное вложение и текст остаются в поле отправки.
- При отсутствии драйвера PostgreSQL сервер не переключается на временный SQLite.

Проверено локально: 15 серверных и 5 клиентских автоматических тестов.
Серверные тесты используют отдельную временную SQLite-базу; поведение
ошибочной транзакции PostgreSQL проверено на модели. Доступ к рабочей Neon
не использовался, проверка на настоящем PostgreSQL пока не выполнена.
Работающий сайт этими локальными изменениями ещё не обновлён.

Файлы, которые старый сервер уже отбросил и не записал в базу, нужно
отправить заново: исправление не может восстановить отсутствующие данные.
